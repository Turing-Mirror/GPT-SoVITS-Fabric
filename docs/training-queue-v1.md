# 训练队列 v1

训练页通过 `train_queue_add` 保存请求并加入队列，使用原有 `train::run` 与 `train_worker.py` 协议串行执行。首个任务加入后开始执行；其他任务按加入顺序等待。用户可以在训练期间修改表单并添加下一任务，切换页面不会中断队列。

## 任务与恢复

- `User_Data/train_queue.json` 保存任务参数、标注快照、阶段、轮数、错误与结果。使用临时文件写入并原子替换，排队命令仅在持久化成功后返回成功。
- 每个任务保留独立参数。数据集已有 `.list` 时，沿用 worker 的排序规则选择首份标注，在加入时保存文本并将音频路径转为原位置的绝对路径。运行时生成 `User_Data/train_queue/<任务编号>.list`，完成后删除临时输入。
- 音频文件不会整套复制。原始音频与未标注数据目录仍须保留；之后修改标注不会改变已加入任务的标注内容。
- 队列使用现有训练执行锁。直接调用训练接口与队列任务不会并行启动训练进程。开始训练仍沿用原有的常驻合成模型释放行为。
- 取消按任务编号定位。启动前取消不会误停另一个直接训练请求；运行中取消沿用进程树停止方式，收尾后才执行下一项。
- 同时等待或运行的任务不能使用映射到同一角色目录的名称，避免一个任务覆盖另一个任务的产物。
- 重启后，未运行任务显示为等待继续，原运行任务显示为训练中断。恢复读取不会启动进程；用户通过继续或重试重新排队。重试保留原参数与标注快照，并遵循原有的续跑选项。
- 可以移除等待任务、重试已结束任务、清除已结束记录。以上操作不删除角色或训练产物。

## 界面与验证

右栏显示名称、版本、训练轮数、当前阶段和任务结果，不展示逐行运行日志。详细日志仍由原有日志系统保存。队列使用现有 TRM UI 分页、状态标签和切换动效，配套八种语言。

Rust 单元测试覆盖串行取任务、取消与移除状态、重启不自动执行、参数与标注快照持久化、角色落点冲突。前端测试覆盖重新进入页面后恢复任务、运行时加入任务、事件与旧快照竞争、操作失败后保留队列。此轮不运行昂贵的真实 GPU 训练；实际训练与主观音色效果由后续实机验收确认。
